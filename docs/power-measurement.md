# 전력 측정

작성일: 2026-09-05
상태: **미완.** 두 번 시도해 두 번 다 실패했다. 아래는 방법·함정·현재 추정치.

---

## 왜 재기 어려운가

이 앱은 화면을 끄지 않는다. 검게 덮을 뿐이라 **디스플레이 파이프라인이 계속 살아 있다.**
그래서 "얼마나 먹는가"가 실제 사용에 직결되는데, 정작 측정이 까다롭다.

## 시도한 방법과 결과

### ❌ `dumpsys battery unplug`

프레임워크가 배터리 방전 중이라고 **인식하게만** 만든다. USB 가 물리적으로 꽂혀 있으면
하드웨어는 계속 충전하므로 쿨롱 카운터가 오히려 **증가한다**(1360625 → 1369375 µAh 관측).

**충전 중에는 측정이 원리적으로 불가능하다.** 케이블을 물리적으로 빼야 한다.

### ❌ sysfs 직접 읽기

`/sys/class/power_supply/battery/{current_now,voltage_now,capacity}` 는 권한이 없어
읽히지 않는다.

### ⚠️ `dumpsys battery` 의 `Charge counter` — 쓸 수는 있으나 해상도 함정

µAh 단위 쿨롱 카운터라 정수 퍼센트보다 훨씬 정밀해 보인다. **하지만 이 기기(S23+)에서는
8750 µAh 단위로만 뛴다.** 화면을 켜고 전류를 쓰는 중에도 60초 동안 값이 전혀 변하지 않는
것을 확인했다.

3분 창에서 이 눈금은 175 mA 에 해당한다. 즉 **3분 측정은 측정이 아니라 양자화 잡음이다.**
실제로 아래 값들을 얻었고 전부 무효였다.

| 조건 | 관측 | 실제 의미 |
|---|---|---|
| 화면 켜짐 | 175.0 mA | 눈금 1개 |
| Screen Off + 시계 | 261.0 mA | 눈금 1.5개 |
| Screen Off 무표시 | 174.0 mA | 눈금 1개 |
| 화면 꺼짐 | 0.0 mA | 눈금 0개 |

**한 조건당 최소 30분**은 돌려야 눈금이 10개 이상 쌓여 오차 10% 안으로 들어온다.

### 유효성 교차검증

30% 시점 카운터가 1,347,500 µAh 였다 → 완충 약 4,500 mAh. S23+ 사양(4,700 mAh)과
맞으므로 **카운터 자체는 신뢰할 수 있다.** 문제는 해상도뿐이다.

## 그 밖의 함정

- **화면이 꺼지면 딥슬립에 들어가 무선 ADB 의 `adb shell sleep` 이 멈춘다.**
  대기는 호스트 쪽에서 하고, 카운터 읽기에는 재연결 재시도를 넣어야 한다.
- **폰이 잠겨 있으면 탭이 전부 잠금화면에 떨어진다.** 2차 시도에서 이것 때문에
  Screen Off 가 켜지지도 않은 채 30분을 쟀다(`accWin=0` 이 증거).
  측정 스크립트는 **각 조건 시작 시 상태를 검증하고 어긋나면 즉시 중단해야 한다.**
  로그에 남기기만 하면 30분을 버린다.
- 화면 타임아웃이 측정 시간보다 짧으면 중간에 잠긴다. 미리 늘리고 끝나면 원복할 것.

## 제대로 재는 절차

1. `adb tcpip 5555` → `adb connect <ip>:5555` 로 무선 전환
2. **USB 케이블을 물리적으로 분리**
3. 폰 잠금 해제, `screen_off_timeout` 을 측정 시간보다 길게 설정
4. 조건당 **30분**, 각 조건 시작 시 아래를 검증하고 어긋나면 중단
   - 접근성 창 개수(`dumpsys window windows | grep -c ty=ACCESSIBILITY_OVERLAY`)
   - 밝기 오버라이드(`dumpsys display | grep mWindowManagerBrightnessOverride`)
   - 잠금 상태(`isKeyguardShowing=false`)
5. 결과에 **눈금 개수를 함께 기록**할 것. 눈금이 적으면 그 값은 못 믿는다
6. `screen_off_timeout` 원복

측정할 조건:

| | 내용 |
|---|---|
| A | 화면 켜짐 (런처) — 기준선 |
| B | Screen Off + 시계 (패널 0.30) |
| C | Screen Off 무표시 (패널 0.00) — **앱 기본 상태** |
| D | 실제 화면 꺼짐 — 하한선 |

**C 와 D 의 차이가 "이 앱을 쓰는 대가"** 라 가장 중요하다.

## 실측 결과 (2026-09-08, Galaxy S23+ / Android 16)

USB 분리, 무선 adb, 조건당 30분, 5분마다 상태 검증. 배터리 38% → 29%.
용량은 이 측정에서 역산했다 — 8% 하락에 337k µAh 였으므로 100% ≈ 4.2 Ah.

| 조건 | 내용 | 평균 전류 | 눈금 | 8시간 (4.2 Ah 기준) |
|---|---|---|---|---|
| A | 화면 켜짐 (런처) | **209.5 mA** | 12.0 | 40% |
| B | Screen Off + 시계 (패널 0.30) | **183.3 mA** | 10.5 | 35% |
| C | Screen Off 무표시 (패널 0.00) — 앱 기본 | **183.3 mA** | 10.5 | 35% |
| D | 실제 화면 꺼짐 (패널 OFF) | **96.1 mA** | 5.5 | 18% |

### 읽는 법

- **이 앱을 쓰는 대가(C − D) ≈ 87 mA.** 밤새 8시간이면 **17% 포인트**를 더 쓴다
  (35% vs 18%). 예전 추정치 "15% 안팎" 은 앱 자체 소모를 절반쯤 낮게 봤다.
- **B = C.** 시계를 켜고 패널을 0.30 으로 올려도 무표시와 눈금 하나도 차이가 없다.
  30분 측정의 해상도가 17.5 mA 이니 그 아래다. "밝기 슬라이더는 전력에 거의 영향이 없다"
  는 예상이 맞았다 — 비용은 켜진 픽셀이 아니라 **화면이 켜져 있다는 사실**에서 나온다.
- **A − C ≈ 26 mA.** 런처를 켜 두는 것보다는 확실히 낫다. 그러나 "화면을 끈 것처럼"
  보이는 것과 실제로 끄는 것의 차이(87 mA)가 그보다 세 배 크다.

### D 는 상한이다

D 를 재는 동안에도 무선 adb 가 붙어 있었고 5분마다 상태를 읽었다. Wi-Fi 와 adbd 가
깨어 있어 기기가 깊은 절전에 못 들어갔을 가능성이 높다 — 96 mA 는 "화면만 끈 폰" 으로는
높은 값이다. 진짜 화면 꺼짐은 이보다 낮을 것이고, 그러면 **C − D 는 87 mA 보다 크다.**
A~C 는 같은 조건에서 재서 서로 비교하는 데는 문제가 없다.

### 측정 중 걸린 것

- `wm density` 는 두 줄(Physical / Override)을 낸다. `tail -1`.
- 슬라이더를 탭한 직후의 `uiautomator dump` 은 애니메이션 중이라 빈 파일을 낸다. 재시도.
- 해제 제스처를 짐작하고 스와이프하지 말 것. `run-as` 로 DataStore 를 `strings` 하면
  `unlock_gesture TRIPLE_TAP` 처럼 값이 보인다. 트랙이 없는데 트랙을 찾다 30초를 버렸다.
- 기능 테스트를 D **앞에** 두어야 한다. D 에서 화면을 끄면 잠기고, 잠금은 adb 로 못 푼다.

## 예전 추정치 (실측 전, 참고용)

> 아래는 실측 전에 쓴 것이다. Screen Off 자체 소모를 절반쯤 낮게 봤다.

### 추정 근거였던 것

버려진 30분 측정 하나가 유효한 데이터를 남겼다 — 잠금화면 10분 + 화면 꺼짐 20분이
섞인 구간에서 눈금 3개(26250 µAh), 평균 52.5 mA. 여기서 역산하면:

```
(10분 × 화면켜짐 + 20분 × 화면꺼짐) / 30분 = 52.5 mA
화면 꺼짐을 10~20 mA 로 두면  →  화면 켜짐 ≈ 120~140 mA
```

| 상태 | 추정 전류 | 8시간 |
|---|---|---|
| 실제 화면 꺼짐 | 5~20 mA | 약 2% |
| **Screen Off (이 앱)** | **70~110 mA** | **12~20%** |
| 일반 화면 켜짐 | 120~140 mA | 21~25% |

**밤새 8시간이면 배터리 15% 안팎.** ← 실측은 35% (위)

### 밝기 슬라이더는 전력에 거의 영향이 없을 것

AMOLED 는 검은 픽셀이 발광하지 않는다. 이 앱은 화면의 대부분이 검정이고 시계 몇 글자만
켜지므로, 밝기를 올려도 켜진 픽셀이 워낙 적어 발광 전력 증가가 미미하다.

전력의 대부분은 **"화면이 기술적으로 켜져 있다"** 는 사실 자체에서 나온다 —
SoC·디스플레이 파이프라인·터치 패널이 계속 깨어 있다. 그래서 실제 화면 꺼짐과
이 앱 사이에 큰 격차가 생긴다.
