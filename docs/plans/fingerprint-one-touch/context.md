# context — fingerprint-one-touch

> **이 문서는 사후에 고쳐 쓰지 않는다.** 작성 시점(2026-09-15)의 판단 기록이다.
> **조사만 했고 구현하지 않았다.** 사용자 지시: "B 를 일단 조사만 해서 문서로 남겨놔. 구현은 ㄴㄴ."

## 원 요청

지문으로 해제를 넣고 실기기로 확인한 직후 사용자가 알아챘다 —

> "아 푸는게 화면이 검정 상태에선 안 되고 반투명 상태에서만 지문이 되는구나"

지금 구현(`491447c`)은 두 동작이다: **탭** → 시스템 프롬프트가 센서를 켬(차폐는 알파 0.55) →
**손가락** → 해제. 사용자가 원하는 것은 잠금화면처럼 **센서에 손가락을 대는 한 동작**으로 풀리는 것.

세 갈래를 제시했다.

| 안 | 내용 | 결정 |
|---|---|---|
| A | 프롬프트 동안에도 검정 유지(반투명 제거) | **폐기.** 아이콘이 안 보여 어디를 짚을지 알 수 없다 |
| B | 센서 자리를 꾹 누른 채로 — 닿는 순간 프롬프트를 켜고, 이미 대고 있는 손가락을 읽게 | **조사만** (이 문서) |
| C | 지금 그대로 (탭 → 반투명 → 지문) | 현 상태 유지 |

## 왜 검정 상태에서는 안 되나 — 확인된 사실

화면 내장 지문 센서는 상시 대기하지 않는다. **`BiometricPrompt` 세션이 살아 있는 동안만** 켜진다.
잠금화면에서 바로 되는 것은 잠금화면(SystemUI)이 세션을 상시 유지하기 때문이고, 일반 앱은
그럴 권한이 없다. 세션은 약 30초 뒤 시간 초과로 끝난다.

그래서 어떤 구현을 하든 **"무언가가 프롬프트를 켠 뒤에" 손가락이 읽힌다.** B 는 그 "무언가" 를
손가락이 닿는 순간 자체로 만들자는 것이다.

## 실기기에서 확인된 것 (2026-09-15, Galaxy S23+ / Android 16)

- 차폐(접근성 오버레이) 탭 → 투명 Activity → 프레임워크 `BiometricPrompt` → `BiometricPromptRoot`
  창 생성 → 손가락 → **65초 안에 해제.** 로그: `FingerprintService: handleAcquired: acquiredInfo=6`.
- **우리 오버레이가 터치를 전부 삼키는데도 센서가 손가락을 읽었다.** 이것이 핵심 관찰이다(아래).
- 프롬프트 UI 는 `screencap` 에 찍히지 않는다. 차폐 반투명은 내비바가 비치는 것으로 확인했다.
