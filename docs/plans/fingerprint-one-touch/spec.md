# spec — fingerprint-one-touch (조사 결과)

**상태: 조사만. 구현하지 않음.** 아래는 구현에 들어갈 경우의 설계와, 그 전에 반드시 실험으로
답해야 하는 질문들이다.

## 목표

차폐 화면에서 **센서 자리에 손가락을 대고 있는 것만으로** 풀린다. 탭이라는 별도 동작이 없다.

## 핵심 가정과 그 근거

### 가정 1 — 센서는 우리 창과 무관하게 손가락을 읽는다 (S23+ 에서 확인됨)

AOSP 의 화면 내장 지문(UDFPS, Android 12+)은 **SystemUI 가 터치 이벤트로 "손가락이 닿았다" 를
판정해 HAL 에 알린다**(`UdfpsController` → `onPointerDown`). 이 방식이면 우리 접근성 오버레이가
터치를 삼키는 순간 SystemUI 는 손가락을 모르고, 센서는 절대 읽지 못한다.

그런데 S23+ 에서는 오버레이가 터치를 삼키는 채로 **읽혔다.** 삼성(퀄컴 초음파 센서)은 손가락
감지를 **하드웨어/HAL 이 직접** 하고 SystemUI 터치에 의존하지 않는다는 뜻이다. B 가 가능한
전제는 여기서 나온다.

> **이식성 경고.** Pixel 같은 AOSP 광학 UDFPS 기기에서는 **지금의 C 방식조차 동작하지 않을 수
> 있다** — 프롬프트는 뜨지만 두 번째 터치가 SystemUI 에 닿지 않는다. 이 앱은 S23+ 개인용이라
> 문제가 아니지만, 기기를 바꾸면 지문 해제는 다시 검증해야 한다. 측면(전원 버튼) 센서 기기는
> 화면과 무관하니 어느 방식이든 동작한다.

### 가정 2 — 세션이 시작될 때 **이미 닿아 있는** 손가락을 읽는다 (미확인, 실험 필요)

B 의 성패가 여기 달렸다. 많은 HAL 은 "손가락이 내려오는 전이" 를 기다린다. 세션이 시작된 뒤
손가락이 **계속 대고 있으면** 전이가 없어서 안 읽을 수 있다. 삼성 초음파 센서가 세션 시작 시
현재 상태를 스캔하는지, 전이만 기다리는지는 공개 자료가 없다. **실험으로만 답이 나온다.**

- 읽으면 → B 성립. 손가락 하나로 끝.
- 안 읽으면 → "댄 채로 살짝 떼고 다시 대기" 가 필요해지고, 그건 C 와 다를 바 없다. B 폐기.

### 가정 3 — 센서 위치를 알 수 있다 (부분적)

한 동작으로 하려면 **어디를 눌러야 프롬프트를 켤지** 정해야 한다. 아무 데나 닿으면 켜는 것은
주머니 문제(아래)를 키운다.

- 공개 API 없음. `FingerprintSensorPropertiesInternal.sensorLocations` 는 hidden.
- `adb shell dumpsys fingerprint` 에 센서 좌표가 찍힐 가능성이 있다 — 개인용이라면 **좌표를
  설정값으로 박아 두는 것**도 답이다. S23+ 는 하단 중앙 고정.
- 대안: 화면 하단 1/4 영역만 트리거 영역으로 잡는다. 정밀하지 않아도 된다 — 트리거는 영역,
  실제 판독은 센서가 한다.

## 위험 — 주머니와 생체 잠금

**프롬프트를 자주 켜면 생체 잠금(lockout)을 부를 수 있다.** 지문 인식 실패가 5회 누적되면
30초 잠금, 계속 쌓이면 PIN 을 넣기 전까지 지문이 막힌다. 이것은 **폰 전체**에 걸린다 — 우리
앱이 잠금화면의 지문까지 망가뜨릴 수 있다는 뜻이다.

- C(지금): 의도적인 탭 뒤에만 세션이 열린다. 주머니 마찰이 실패로 쌓일 창이 좁다.
- B: 손가락(또는 주머니 천)이 트리거 영역에 닿을 때마다 세션이 열린다. **천이 센서에 닿으면
  실패로 셈해질 수 있다.** 최소 완화: 300ms 이상 눌려 있을 때만 켜기, 트리거 영역을 센서
  주변으로 좁히기, 연속 실패를 세서 스스로 잠시 멈추기.

**전력.** 세션마다 SystemUI 가 깨고 센서가 켜진다. 주머니에서 반복되면 실측한 87 mA 위에 얹힌다.
양은 재봐야 안다.

## 구현하게 된다면

1. `FingerprintUnlockLayer` 를 **`ACTION_DOWN` 트리거**로 바꾼다 (지금은 탭 = 뗄 때). 300ms 유지 조건.
2. 트리거 영역을 하단 영역(또는 설정된 센서 좌표 반경)으로 제한.
3. 프롬프트가 떠 있는 동안은 재트리거하지 않는다 (`BiometricUnlockActivity` 가 `singleTask` 라
   중복은 안 뜨지만, `setBiometricPromptActive` 상태로 막는 것이 명확하다).
4. 실패 카운터: `onAuthenticationFailed` 3회면 60초간 트리거 중단. 잠금화면 지문을 지킨다.
5. 반투명(알파 0.55)은 유지 — A 는 폐기됐다.

## 실험 절차 (구현 전에 할 것)

코드를 최소로 바꿔 가정 2 만 확인한다. 트리거를 `ACTION_DOWN` 으로 바꾼 임시 빌드로:

1. 차폐를 띄운다. 3회 탭 등 다른 해제 수단을 남겨 둔다 (실패 시 빠져나올 길).
2. **센서 자리에 손가락을 대고 그대로 3초 유지.** 떼지 않는다.
3. `adb logcat | grep -E "FingerprintService|BiometricService"` 에서 `handleAcquired` 또는
   `onAuthenticationSucceeded` 가 **손을 떼기 전에** 찍히는지 본다.
4. 안 찍히면 살짝 떼고 다시 댄다 — 이때 찍히면 "전이만 기다린다" 확정 → B 폐기.
5. 각 케이스 3회 반복. 한 번의 성공은 우연일 수 있다.

## 완료 조건 (구현할 때)

- [ ] 센서 자리에 손가락을 대고 있으면 떼지 않고 풀린다 (3회 중 3회)
- [ ] 트리거 영역 밖 터치는 세션을 열지 않는다
- [ ] 주머니 시뮬레이션(천으로 문지르기 30초)에서 생체 잠금이 걸리지 않는다
- [ ] 다른 해제 제스처는 영향 없음
