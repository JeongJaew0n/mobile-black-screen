# context — floating-bubble-launcher

## 사용자의 원 요청

> "이제 다른 앱에서도 screen 커버 앱을 켜고 싶으니까, 이 앱을 닫아도 계속 유지되는
> 동그랗고 작은 버튼을 만들고 싶어."

## 왜 이걸 지금 하는가

`blackout-overlay-modes` 작업으로 두 가지 차폐 모드와 퀵 설정 타일까지 완성해
실기기 검증을 마친 직후다. 현재 차폐를 시작하는 경로는 두 가지뿐이다.

1. 앱을 열어 "차폐 시작" 버튼을 누른다
2. 상태바를 내려 퀵 설정 타일을 누른다

둘 다 **다른 앱을 쓰는 도중에는 한 단계를 거쳐야 한다.** 특히 타일은 알림창을 내리고
타일을 찾아 눌러야 한다. 화면 위에 상주하는 버튼이 있으면 그 단계가 사라진다.

## 결정된 방향

**상주 오버레이 버블 + 서비스 통합.** `OverlayService` 를 `ScreenCoverService` 로
확장해 버블 창과 차폐 창을 함께 관리하는 상태 기계로 만든다.

## 확정된 선택 (사용자 결정)

- **부팅 후 자동 복원: 하지 않는다.** 조사 결과 `specialUse` 포그라운드 서비스는
  `BOOT_COMPLETED` 에서 시작이 허용되어 기술적으로는 가능했다
  (Android 15+ 가 막은 것은 dataSync·mediaPlayback·mediaProjection·phoneCall 뿐).
  가능함을 확인한 뒤 사용자가 수동 재실행을 택했다.
  결과적으로 기존 CLAUDE.md 의 "부팅 후 자동 시작을 넣지 않는다" 결정이 유지된다.
- **버블 제거: 드래그해서 하단 ✕ 타겟에 떨군다.** 메신저 버블과 같은 방식.

## 기각된 대안

- **서비스를 분리해 `BubbleService` 를 새로 만든다** — 기각. 기존 검증 코드를 덜
  건드린다는 장점이 있지만 포그라운드 서비스가 둘이 되어 **상시 알림이 두 개**가 된다.
  "아무것도 없는 화면"을 지향하는 앱에서 알림 두 개는 컨셉과 어긋난다.
- **부팅 시 자동 복원** — 기술적으로 가능했으나 사용자가 수동을 택했다(위 참조).
- **알림의 버튼으로만 버블 끄기** — 기각. 오작동 위험이 없고 구현도 가장 간단하지만,
  끄려면 알림창을 내려야 해서 "알림창을 내리지 않아도 된다"는 이 기능의 존재 이유와
  모순된다.
- **버블 롱프레스 메뉴(설정 / 끄기)** — 기각. 드래그 제스처와 롱프레스를 함께 쓰면
  제스처 구분이 까다로워지고 오인식이 늘어난다.
- **버블 위치를 픽셀 좌표로 저장** — 기각. 회전하거나 다른 해상도에서 복원하면
  화면 밖으로 나간다. 가장자리(LEFT/RIGHT) + 세로 비율(0..1)로 저장한다.
- **접근성 서비스로 최상단 Activity 를 감지해 버블을 숨긴다** — 기각.
  접근성 권한은 이 용도에 과하고 사용자 허들도 크다. `BlackoutActivity` 가
  서비스에 직접 알리면 충분하다.

## 제약 / 합의 사항

### 기술적 제약
- **오버레이는 Activity 보다 위에 그려진다.** 따라서 Blackout 모드 차폐 중에는
  버블을 반드시 숨겨야 하며, 오버레이 창은 어떤 Activity 가 앞인지 스스로 알 수 없다.
- 포그라운드 서비스인 이상 상시 알림을 없앨 수 없다.
- 민감 화면과 `hideOverlayWindows()` 를 부르는 앱 위에서는 버블이 자동으로 숨겨진다.
- **버블을 켜는 순간 Blackout 모드도 `SYSTEM_ALERT_WINDOW` 권한을 요구하게 된다.**
  지금까지 Blackout 은 권한 0개였다.

### 사용자가 명시한 선호
- 버튼은 **동그랗고 작아야** 한다
- **앱을 닫아도 유지**되어야 한다
- 목적은 **다른 앱을 쓰는 도중** 차폐를 켜는 것
