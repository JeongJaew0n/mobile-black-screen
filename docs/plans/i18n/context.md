# context — i18n

> **이 문서는 사후에 고쳐 쓰지 않는다.** 작성 시점(2026-09-07)의 판단 기록이다.

## 원 요청

> "다국어 도입 설계해."

앞선 요청들과 달리 대상 언어가 지정되지 않았다. 그래서 **언어 목록은 파라미터로 두고,
언어를 추가하는 일이 문자열 파일만 늘리는 작업이 되도록 하는 것**을 목표로 삼았다.

## 지금 상태에서 출발점

- `app/src/main/res/values/strings.xml` 에 47개. 로케일별 디렉터리는 없다.
- **기본 로케일이 한국어다.** `values/` 가 한국어라 프랑스어 기기에서도 한국어가 뜬다.
- 코드 안 하드코딩은 두 곳뿐이다 — `AimTargets.kt` 의 `"앱 열기"` / `"버블 삭제"`.
  나머지 한글 리터럴은 전부 주석이다.
- `supportsRtl="true"` 는 이미 켜져 있다. minSdk 26, targetSdk 36.
- appcompat 의존성이 없다. 순수 Compose 앱이다.

즉 **문자열 추출은 거의 끝나 있고, 문제는 문자열이 아닌 것들에 있다.**

## 판단 1 — 기본 로케일을 영어로 옮긴다

`values/` 는 "일치하는 로케일이 없을 때" 쓰이는 최후 폴백이다. 한국어를 여기 두면
목록에 없는 모든 언어가 한국어를 보게 된다. 한국어는 `values-ko/` 로 옮기고
`values/` 를 영어로 만든다.

47개를 영어로 다시 쓰는 마이그레이션 비용이 들지만, 언어를 하나 더 늘릴 때마다
같은 결정을 미루는 비용이 붙는다. 지금 한 번 옮기는 것이 싸다.

## 판단 2 — 앱 안에 언어 선택을 넣지 않는다

Android 13+ 는 시스템 설정에 앱별 언어 항목을 만들어 준다. `localeConfig` 만 선언하면
공짜다. 12 이하에서도 앱 안에서 언어를 바꾸려면 `AppCompatDelegate.setApplicationLocales`
가 필요하고, 그건 **appcompat 의존성과 매니페스트 서비스 등록을 이 앱에 다시 들이는 일**이다.

이 앱은 개인 사이드로딩이고 대상 기기는 Android 16 이다. 12 이하는 시스템 로케일을
그대로 따르게 두고, appcompat 은 들이지 않는다.

## 판단 3 — 시계 형식은 번역이 아니라 **패턴 파생**으로 푼다

지금은 `"a h:mm"`(한국어 순서)를 상수로 박아 두고 있다. 여기에 로케일이 붙으면
언어마다 순서·구분자·숫자 표기가 갈리므로, 로케일별로 패턴 문자열을 번역하는 방식은
곧 무너진다.

`DateFormat.getBestDateTimePattern(locale, "hm")` 이 그 로케일의 올바른 패턴을 준다.
저장값은 **패턴 문자열이 아니라 24/12시간제 두 값 중 하나**여야 한다.

> 이 지점이 이번 설계의 핵심이다. `"h:mm a"` → `"a h:mm"` 로 한 번 고친 적이 있는데,
> 그건 증상을 고친 것이고 원인은 "패턴을 사람이 정한다" 였다.

## 기각한 대안

| 대안 | 기각 이유 |
|---|---|
| 한국어를 `values/` 에 두고 `values-en` 추가 | 목록에 없는 언어가 한국어를 본다 |
| 로케일별로 시계 패턴 문자열을 번역 | 언어마다 검수가 필요하고 틀려도 안 드러난다 |
| appcompat 을 넣고 앱 안 언어 선택 제공 | 대상 기기가 13+ 라 얻는 것이 없다 |
| 기계 번역으로 전 언어 일괄 투입 | OS 용어를 인용하는 문자열이 어긋난다 (아래) |
| `resConfigs` 로 언어 축소 | 사이드로딩이라 APK 크기가 제약이 아니다 |

## 미리 알아 둘 함정

- **OS 용어를 인용하는 문자열이 있다.** `‘다른 앱 위에 표시’`, `‘접근성’` 은 시스템 설정의
  항목 이름이다. 직역하면 사용자가 그 항목을 찾지 못한다. 각 언어의 **플랫폼 표기**를
  그대로 가져와야 한다 (영어: *Display over other apps*, *Accessibility*).
- **Compose 의 `Text("리터럴")` 은 lint 가 잡지 않는다.** `HardcodedText` 는 XML 전용이다.
  추출 누락은 grep 으로 막는 수밖에 없다.
- **알림 채널 이름은 시스템이 캐시한다.** 다행히 `goForeground()` 가 매번
  `createChannel()` 을 부르므로 언어를 바꾼 뒤 서비스가 다시 뜨면 갱신된다.
  채널 생성을 `onCreate` 한 번으로 옮기면 이 성질이 깨진다.
- **`"%.1f".format()` 은 기본 로케일을 쓴다.** 독일어에서 `1,5` 가 된다. 그 자체는 맞지만
  `"초"` 를 문자열 밖에서 이어 붙이고 있어 어순을 바꿀 수 없다.

## 재검토 (같은 날, 커밋 전)

"설계 다시 검토해" 라는 요청으로 한 번 더 봤다. 위 본문은 그대로 두고 틀린 것을 여기 적는다.

**판단 1 의 비용 논리가 틀렸다.** "47개를 영어로 다시 쓰는 비용이 든다" 고 썼는데,
한국어를 기본으로 두고 `values-en` 을 추가해도 영어 47개는 똑같이 써야 한다. 비용은 같다.
두 안의 차이는 **목록에 없는 언어가 무엇을 보는가** 하나뿐이고, 그 답은 영어다.
결론은 같지만 이유를 잘못 적었다.

**시계 형식의 API 선택이 틀렸다.** `android.text.format.DateFormat.getBestDateTimePattern`
+ `java.time` 으로 쓰려 했는데,
(1) 한국어 24시간제 기본이 `H:mm` 이라 지금의 `09:05` 가 `9:05` 로 바뀐다 —
    "한국어는 지금과 동일" 이라는 완료 조건을 내가 스스로 깨는 설계였다.
(2) ICU 패턴에 `B`(유연한 시간대)가 들어오면 `java.time` 이 예외를 낸다.
`android.icu.text.DateTimePatternGenerator` + `MATCH_HOUR_FIELD_LENGTH` + ICU `SimpleDateFormat`
으로 바꿨다. **"패턴을 사람이 정하지 않는다" 는 원칙은 그대로다.** 도구만 바뀌었다.

**RTL 에서 "안 뒤집는다" 고만 썼고 어떻게 안 뒤집을지는 안 썼다.** 코드를 확인하니
`SlideToUnlockLayer` 가 `Alignment.CenterStart` 와 `Modifier.offset { }` 을 쓴다 — 둘 다
기본이 미러링이다. 아무것도 안 하면 손잡이가 오른쪽에서 시작해 손가락 반대로 움직인다.
`LocalLayoutDirection` 을 `Ltr` 로 고정해야 한다.

**앱별 언어가 닿지 않는 곳을 빠뜨렸다.** 런처 앱 이름·타일 이름·접근성 목록 설명은
다른 프로세스가 그리므로 기기 언어를 따른다. 원래 완료 조건 "접근성 설명이 영어다" 는
`set-app-locales` 로는 절대 통과할 수 없는 조건이었다.

**서비스 창의 로케일 고정을 빠뜨렸다.** 다행히 텍스트를 가진 창은 전부 매번 새로 만들어서
지금은 문제가 없지만, 버블 창에 텍스트를 넣으면 깨진다. 규칙으로 적었다.

이 다섯 가운데 넷은 **코드를 안 열어 보고 쓴 것**에서 나왔다. 검토 때 `SlideToUnlockLayer`
와 `Clock.kt` 를 실제로 열어 보고서야 드러났다.
