# spec — media-volume-control

**상태: 설계. 구현 전.** 실측이 필요한 항목은 §실험, 사용자 확인이 필요한 결정은 §결정 대기.

## 목표

차폐가 떠 있는 동안 **미디어 소리(`STREAM_MUSIC`)** 를 끈다. 되돌아오는 방식이 다른 두 가지를
사용자가 고른다.

## 범위

- **포함**
  - 설정 `mediaVolumeAction` — 끔(기본) / 차폐 중 음소거 / 차폐 시 볼륨 0
  - 차폐 시작·종료 지점에 적용·복원
  - 복원을 놓칠 수 있는 모든 경로 처리
- **제외**
  - 알림·통화·알람 스트림 (사용자가 "미디어만" 으로 좁혔다)
  - 볼륨 키 감시 (사용자에게서 회복 수단을 뺏는다 — context.md 기각 목록)
  - 다른 앱 재생을 멈추는 오디오 포커스 방식

## 완료 조건 (Definition of Done)

- [ ] `끔` 이 기본값이고, 이때 볼륨에 손대지 않는다
- [ ] `볼륨 0`: 차폐를 켜면 미디어 볼륨이 0. **해제해도 0 그대로**
- [ ] `일시 음소거`: 차폐를 켜면 소리가 안 나고, **해제하면 원래 볼륨으로 정확히 복원**
- [ ] 복원이 아래 **모든** 경로에서 일어난다
  - 해제 제스처 / 지문 인증 성공 / 시스템이 창을 걷어감(PIN 화면) / 서비스 소멸
- [ ] 볼륨을 바꿀 때 **시스템 볼륨 팝업이 뜨지 않는다** (차폐 위에 뜨면 검정이 깨진다)
- [ ] 차폐 중 사용자가 볼륨 키를 올리면 소리가 나온다 (감시하지 않는다)
- [ ] 재생 바는 그대로 동작한다 — 소리만 없고 제목·진행·제어는 살아 있다
- [ ] 새 권한을 요구하지 않는다
- [ ] lint 0 errors

## 설계

### 1. 설정

```kotlin
enum class MediaVolumeAction { NONE, MUTE_WHILE_COVERED, SET_TO_ZERO }
// Settings 에 val mediaVolumeAction: MediaVolumeAction = NONE
```

라디오 3택. 스위치 두 개로 두지 않는 이유는 context.md 참조.
`화면 표시` 가 아니라 **`설정` 탭**에 둔다 — 화면에 무엇이 보이는가가 아니라 차폐가 무엇을
하는가에 대한 설정이다.

### 2. 적용 지점 — 차폐 수명에 정확히 붙인다

차폐 창의 수명은 `ScreenOffAccessibilityService` 가 쥐고 있고, **이미 세 경로 전부에 정리 훅이
있다.** 재생 바(`MediaWatcher`)가 같은 문제를 풀어 둔 자리에 나란히 붙이면 된다.

| 지점 | 지금 하는 일 | 추가할 일 |
|---|---|---|
| `showCover()` | `syncMediaWatcher()` · `applyBrightness()` | **볼륨 적용** |
| `hideCover()` | `mediaWatcher.stop()` | **복원** |
| `onViewDetachedFromWindow` | `syncMediaWatcher()` | **복원** (시스템이 창을 걷어간 경우) |
| `onDestroy()` | `mediaWatcher.stop()` | **복원** |

> ⚠️ `hideCover()` 는 `coverView ?: return` 으로 시작해 **창이 없으면 아무것도 하지 않는다.**
> `onDestroy` 에서 복원을 `hideCover()` 에 맡기면 안 된다 — 이미 `mediaWatcher.stop()` 에서
> 같은 함정을 밟아 고친 적이 있다(커밋 `c161d3e`). 직접 부른다.

### 3. `볼륨 0` — 복원하지 않는다

```kotlin
audioManager.setStreamVolume(AudioManager.STREAM_MUSIC, 0, 0)   // flags=0 → 팝업 없음
```

차폐를 켤 때 한 번 내리고 끝이다. 해제해도 그대로 두는 것이 이 선택지의 정의다.
**복원 로직이 없으므로 복원 실패 위험도 없다.**

### 4. `일시 음소거` — 복원이 전부다

두 방식 중 하나를 실험 결과로 고른다.

**(a) 시스템 음소거** — `adjustStreamVolume(STREAM_MUSIC, ADJUST_MUTE, 0)` / `ADJUST_UNMUTE`
시스템이 이전 볼륨을 기억한다. 우리가 값을 들고 있지 않아 저장 실패로 어긋날 일이 없다.
다만 **프로세스가 죽어도 음소거가 남는다면** 강제 종료 시 소리가 안 돌아온다.

**(b) 직접 저장·복원** — 켤 때 `getStreamVolume` 으로 읽어 두고 0 으로, 끌 때 되돌린다.
저장값을 **DataStore 에 둔다.** 메모리에만 두면 서비스가 죽을 때 사라진다.
앱을 다시 열 때 저장값이 남아 있으면 복원하고 지운다 — 강제 종료에 대한 보험이다.

현재 기운 쪽은 **(b)** 다. 이 저장소는 "시스템이 우리 대신 상태를 기억해 주는 것" 에 두 번
데였다(창을 걷어가는 문제, `collectAsStateWithLifecycle` 의 옛 스냅샷). 다만 (a)가 정확히
동작하고 프로세스와 함께 풀린다면 (a)가 더 단순하다 — **실험 1·2 의 결과로 정한다.**

### 5. 볼륨 키를 감시하지 않는다

차폐 중 사용자가 볼륨을 올리면 소리가 난다. 그대로 둔다.
"일시 음소거" 가 조작 한 번에 풀리는 셈이지만, 감시하면 사용자가 소리를 되찾을 수단이 사라진다.
지문 갇힘에서 배운 것과 같다 — **앱이 사용자의 회복 수단을 막지 않는다.**

이 경우 해제 시 복원은 어떻게 하는가: **(b) 방식이면 저장해 둔 옛 볼륨으로 덮어쓴다.**
사용자가 중간에 올린 값은 사라진다. 대안은 "현재 값이 0이 아니면 복원하지 않기" 인데,
그러면 사용자가 잠깐 올렸다 내린 경우에 복원이 안 된다. **덮어쓰는 쪽이 단순하고 예측 가능하다.**

## 실험 (구현 첫 단계에서 실기기로)

```bash
# 현재 미디어 볼륨 / 최대값
adb shell dumpsys audio | grep -A5 "STREAM_MUSIC"
adb shell media volume --stream 3 --get        # 3 = STREAM_MUSIC
```

1. **`ADJUST_MUTE` 가 권한 없이 동작하는가.** 앱에서 호출 → `dumpsys audio` 로 확인.
2. **시스템 음소거가 프로세스와 함께 풀리는가.** 음소거 후 `am force-stop` → 소리가 돌아오는가.
   돌아오지 않으면 (a) 폐기, (b) 채택.
3. **블루투스 연결 시 어느 볼륨이 바뀌는가.** 블루투스 스피커 연결 후 차폐 → 스피커 소리가
   꺼지는가. **사용자 확인 필요(§결정 대기 2).**
4. **`flags = 0` 으로 볼륨 팝업이 안 뜨는가.** 차폐 위/아래 어디에도 안 보여야 한다.
5. **차폐 중 볼륨 키를 올리면** 소리가 나는가, 해제 시 복원이 어떻게 되는가.

## 함정 예상

- **`hideCover()` 의 조기 반환** — §2 경고 참조. 같은 실수를 한 번 했다.
- **고정 볼륨 기기**(`audioManager.isVolumeFixed`) — TV·일부 기기는 볼륨 조작이 무시된다.
  그런 기기에서는 설정을 감추거나 안내해야 한다.
- **차폐를 두 번 켜는 경우** — 저장값을 덮어써 0 을 "원래 볼륨" 으로 기억할 수 있다.
  적용 시 **이미 적용 중이면 저장하지 않는다**는 가드가 필요하다.
- **Blackout / Overlay 모드** — 지금은 미제공이라 FULL 만 다룬다. 되살릴 때 같은 훅이 필요하다
  (`architecture.md` §4.2 의 빚 목록에 함께 적을 것).

## 결정 대기

1. **`볼륨 0` 을 고른 상태에서 차폐를 켤 때마다** 볼륨을 0 으로 내리는가, 아니면 처음 한 번만인가?
   — 제안: **켤 때마다.** 사용자가 올려 둔 뒤 차폐를 켜면 다시 0 이 되는 것이 "차폐 = 조용히" 라는
   의도에 맞다. 한 번만 하려면 "이미 했음" 상태를 저장해야 하는데 그 복잡도가 값을 못 한다.
2. **블루투스로 듣는 중에도 끄는가?** 처음 "블루투스 외의 소리" 라고 하신 말이 걸린다.
   Android 는 출력 장치별로 볼륨을 따로 기억해서, 블루투스 연결 중이면 블루투스 볼륨이 0 이 된다.
   — 제안: **구분하지 않는다.** "미디어 소리만" 이라는 정정을 그대로 따르고, 출력 장치로 나누는
   것은 동작을 설명하기 어렵게 만든다. 다만 의도와 다르면 지금 말씀해 주셔야 한다.
