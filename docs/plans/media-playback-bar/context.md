# context — media-playback-bar

> **이 문서는 사후에 고쳐 쓰지 않는다.** 작성 시점(2026-09-15)의 판단 기록이다.
> **설계 검토 단계.** 구현 전.

## 원 요청

> "음악, 유튜브(동영상) 재생되고 있을 때 재생 바 표시."

지문 해제는 현 상태(탭 → 프롬프트 → 지문)로 확정하고 넘어왔다.

## 이 앱에서 이 기능이 자연스러운 이유

FULL 모드는 **아래 앱을 멈추지 않는다.** 유튜브를 틀어 놓고 Screen Off 를 하면 영상은 검은 창
아래에서 계속 재생된다(RESUMED). 프리미엄 없이도 "화면 끄고 유튜브 듣기" 가 되는 셈이다 —
이 앱의 부수 효과 중 가장 실용적인 것. 재생 바는 그 상태를 눈으로 확인하는 수단이다.

## 가장 큰 결정 — 권한 하나가 더 필요하다

"무엇이 재생 중인가" 를 아는 공개 경로는 하나다: `MediaSessionManager.getActiveSessions()`.
이 API 는 **알림 접근 권한**(Notification access)이 있는 `NotificationListenerService` 컴포넌트를
요구한다. 잠금화면의 미디어 컨트롤이 쓰는 것과 같은 경로다.

권한 없이 알 수 있는 것은 `AudioManager.isMusicActive()` — "무언가 소리를 낸다" 는 참/거짓뿐이다.
어떤 앱인지, 제목이 무엇인지, 몇 분 남았는지는 없다. `AudioPlaybackConfiguration` 은 재생 중인
스트림 목록을 주지만 어느 앱인지(uid)는 hidden API 다.

| 경로 | 얻는 것 | 권한 |
|---|---|---|
| `MediaSessionManager` | 제목·아티스트·앱·위치/길이·재생 상태·제어 | **알림 접근** |
| `AudioManager.isMusicActive` | 재생 중 여부만 | 없음 |

이 앱은 이미 접근성(차폐)·다른 앱 위에 표시(버블) 두 개의 특수 권한을 받는다. 셋째가 된다.
개인 사이드로딩이라 심사 문제는 없지만, **알림 접근은 모든 알림 내용을 읽을 수 있는 권한**이다.
접근성에서 `canRetrieveWindowContent=false` 로 "읽지 않는다" 를 선언한 것과 달리, 알림 접근에는
그런 플래그가 없다 — 콜백을 비워 두는 것으로만 약속할 수 있다. 설정 화면 문구에 그 사실을 적는다.

## 결정 — 1차는 표시만, 제어 없음

재생/일시정지/다음 곡 버튼을 넣으면 **해제 제스처와 충돌한다.** 3회 탭·더블 탭은 화면 어디를
눌러도 세는데, 버튼 영역의 탭을 빼려면 제스처 레이어를 손대야 한다. 가능하지만 1차 범위가
아니다. 표시만 있어도 요청("재생 바 표시")은 충족된다. 제어는 2차.

## 결정 — 진행 막대는 초 단위로 움직이지 않는다

시계를 분 단위로만 갱신하는 것과 같은 이유다. 초마다 프레임을 그리면 8시간 내내 1Hz 로 깨어
있는 셈이다. 위치는 `PlaybackState` 의 `position + (now − lastPositionUpdateTime) × speed` 로
언제든 계산할 수 있으니, **10초마다 한 번** 다시 그리고 상태 변화(곡 바뀜·일시정지)는 콜백으로
즉시 반영한다. 검은 화면을 흘끗 보는 용도에 10초 해상도는 충분하다.

## 기각한 대안

| 대안 | 기각 이유 |
|---|---|
| 앨범 아트 표시 | 밝은 이미지는 "완전한 검정" 과 어긋나고 번인 위험. 글자만 |
| 알림 내용 파싱(미디어 알림에서 제목 추출) | 같은 권한을 쓰면서 더 부서지기 쉽다. `MediaSession` 이 정식 경로 |
| `isMusicActive` 로 "재생 중" 표시만 | 재생 바가 아니다. 다만 **권한을 거부했을 때의 폴백**으로는 쓸 만하다 |
| 초 단위 진행 막대 | 전력. 위 참조 |
