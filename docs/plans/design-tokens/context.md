# 왜 시작했는가

> 이 문서는 사후에 고쳐 쓰지 않는다. 2026-09-23 시점의 판단 기록이다.

## 원 요청

> 여기서 디자인 토큰을 뽑아내줘. 기술 종속인거 말고. 다른 제품에서도 재활용할 수 있고
> 또한 여기서도 값만 수정하면 다른 디자인을 적용할 수 있도록 설계해줘.

세 조건이다.

1. **기술 종속이 아닐 것** — Compose `Color`/`Dp` 가 원본이면 안 된다.
2. **다른 제품에서 재활용** — 이 앱의 부품 이름이 아니라 의도 이름으로 되어 있어야 가져갈 수 있다.
3. **값만 고쳐서 다른 디자인** — 시각 결정이 코드 안 리터럴로 남아 있으면 안 된다.

## 출발점

`ui/theme/Tokens.kt` 에 토큰 4개(`FloatingSurface`·`FloatingBorder`·`FloatingContent`·
`SecondaryAlpha`)가 있었다. 기준은 "두 곳 이상 반복되는 값만" 이었고, 나머지 시각 값은
쓰이는 자리에 리터럴로 두었다 — "왜 이 값인가" 가 옆 주석에 붙어 있어야 읽힌다는 이유였다.

이번 요청은 그 기준을 뒤집는다. 조건 3 은 **한 곳에서만 쓰이는 값도** 토큰이어야 한다는
뜻이다. 근거를 잃지 않으려면 근거가 토큰과 함께 이동해야 한다 — 그래서 원본 형식에
`$description` 이 있는 것이 중요했다.

## 결정

### 원본은 W3C Design Tokens(DTCG) JSON, Kotlin 은 생성물

`design/tokens/tokens.json` 이 유일한 원본이다. `ui/theme/Tokens.kt` 는 `build.py` 가 만든다.
Kotlin 을 손으로 고치면 다음 생성에서 사라진다 — 그래서 파일 머리에 크게 적고,
`build.py --check` 로 어긋남을 잡는다.

DTCG 를 고른 이유: 형식이 표준이라 Style Dictionary·Tokens Studio 같은 도구가 그대로 읽는다.
다른 제품(웹·iOS)이 이 JSON 을 가져가면 그쪽 파이프라인이 알아서 CSS 변수·Swift 로 뽑는다.
조건 1·2 를 형식 하나로 만족한다.

### 세 층 — ref / sys / comp

Material 의 `md.ref / md.sys / md.comp` 어법이다. Android 개발자에게 익숙하고, 층의 규칙이
명확하다: **sys 는 ref 만 가리키고, comp 는 sys·ref 만 가리킨다.** 역방향은 없다.

- `ref` — 값 그 자체. `palette.ink900`, `dimension.d8`, `opacity.o70`. 이름에 의도가 없다.
- `sys` — 의도. `color.canvas`, `color.floatingSurface`, `opacity.secondary`, `spacing.md`.
  **다른 제품에 가져가는 층.**
- `comp` — 부품. `bubble.surface`, `mediaBar.lift`, `unlockRing.size`. 이 앱 것이다.

"값만 고쳐서 다른 디자인" 은 `ref` 를 갈아 끼우거나(팔레트 교체) `sys` 의 alias 를 바꾸는
것(의도 재배치)으로 된다. `comp` 는 건드릴 일이 거의 없다.

### 이번 추출은 시각 변화 0

값을 보면 정리하고 싶어진다 — 0.22 와 0.25 는 둘 다 "흐린 선", 150ms 와 160ms 는 둘 다
"빠른 반응" 이다. **하지만 통합은 디자인 결정이고 눈으로 봐야 한다.** 추출은 리팩터링이라
빌드 전후 화면이 같아야 검증할 수 있다. 통합 후보는 `checklist.md` 에 남긴다.

### 토큰이 아닌 것

디자이너가 바꾸는 값만 토큰이다. 아래는 시각처럼 보이지만 **동작·하드웨어 상수**라 코드에
남긴다.

| 값 | 왜 토큰이 아닌가 |
|---|---|
| 겨냥 임계 44dp, 탭 창 400ms, 밀어내기 0.28, 해제 지점 0.92 | 제스처 판정. 바꾸면 디자인이 아니라 **동작**이 바뀐다 |
| 번인 궤도 8dp×28dp / 60초 / 12스텝 | 패널 보호 파라미터. 다른 제품에서 재활용할 값이 아니다 |
| 패널 밝기 0.30 | 전력 실측으로 정한 값 (`power-measurement.md`) |
| 기호 내부 비율(0.35, 0.14, …), 배터리 번개 좌표 | 아이콘의 **그림** 이다. SVG path 를 토큰으로 안 빼는 것과 같다 |
| `holdMillis`·`bubbleSizeDp` 기본값과 범위 | 사용자 설정이다 |

## 기각한 대안

**CompositionLocal 테마 (런타임 교체).** 요청은 "값만 수정하면" 이지 "실행 중 바꿔 끼우기" 가
아니다. 그리고 이 앱은 Compose 밖(서비스·`LayoutParams`)에서도 값을 쓴다 — 정적 `object`
는 어디서든 읽히지만 CompositionLocal 은 컴포지션 안에서만 읽힌다.

**Style Dictionary(Node) 로 생성.** 표준 도구지만 이 저장소에 Node 의존을 들이는 값어치가
없다. 필요한 변환은 "JSON → Kotlin 상수" 하나뿐이고 Python 표준 라이브러리로 100줄이다.
JSON 이 DTCG 형식이니 **다른 제품은** Style Dictionary 를 써도 된다 — 그게 형식을 표준으로
고른 이유다.

**Gradle 태스크로 생성을 빌드에 묶기.** 빌드마다 돌면 드리프트가 원천 차단되지만
buildSrc 에 JSON 파서를 들이고 빌드가 느려진다. 생성물을 커밋하고 `--check` 로 잡는 쪽이
이 규모에 맞다. 드리프트가 실제로 문제가 되면 그때 옮긴다.

**Material `colorScheme` 을 토큰으로 채우기.** 설정 화면은 `darkColorScheme()` 기본을
쓴다. 지금 화면에 문제가 없고, 토큰 → colorScheme 매핑은 설정 화면 디자인을 정할 때
같이 하는 게 맞다. 이번 범위 밖.

**값 정리(통합)를 함께 하기.** 위 "시각 변화 0" 절.
