## 이번에 하는 것과 안 하는 것

| 연구 순위 | 항목 | 이번 | 이유 |
|---|---|---|---|
| 1 | 해제 방법을 보이게 | **한다** | 가장 싸고, 처음 쓰는 사람이 갇히는 문제 |
| 2 | 자동 종료 타이머 | **한다** | 배터리를 실제로 줄이는 유일한 길 |
| 3 | 권한 안내 | **한다** | 남에게 주면 기본 모드가 안 켜진다 |
| 6 | `볼륨 0` 을 드러내기 | **한다** | 1번과 같은 자리에 한 줄 |
| 4 | 재생 컨트롤을 탭해야 보이게 | 안 한다 | 선택 항목이 하나 늘고, 불편을 겪는지 사용자에게 아직 들은 적이 없다 |
| 5 | 전화가 오면 | 안 한다 | 실험이 먼저인데, 이 기기로 전화를 걸어 줄 사람이 있어야 한다 |

## 구현 계획 때 바뀐 판단 두 가지

1. **타이머가 끝나면 화면을 진짜로 끈다.** 연구에서는 "차폐를 풀면 시스템 꺼짐 시간이 이어받는다" 고
   했는데, 이 기기의 꺼짐 시간은 24시간이다. 차폐만 풀면 밝은 화면이 켜진 채 남는다 — 타이머가 없느니만
   못하다. 접근성 서비스의 `performGlobalAction(GLOBAL_ACTION_LOCK_SCREEN)`(API 28+)으로 잠그면 화면이
   실제로 꺼진다. 미디어는 멈추지 않는다 — **화면 타이머**다. 수면 타이머(재생도 멈춤)는 사용자가 원하면
   선택지로 더한다.
2. **"조용한 실패" 는 없었다.** 연구에서 타일·버블로 켜면 아무 일도 없다고 썼는데, 코드를 보니 세
   진입점 모두 접근성 설정을 연다. 문제는 **왜 열렸는지 말하지 않는 것**이라 토스트 한 줄로 줄였다.

## 설계 결정

- **안내 문구는 차폐 창에만.** 버블 창에 텍스트 금지(로케일이 굳는다). 차폐 창은 켤 때마다 새로 만든다.
- **안내가 떠 있는 동안만 밝기 0.30.** 밝기를 정하는 곳은 `effectiveBrightness()` 하나 — 여기에 "안내
  표시 중" 을 더한다. 0.30 과 0 은 실측 전력이 같아 비용이 없다.
- **안내 트리거는 해제 제스처의 첫 동작 그 자체.** 3회 탭의 첫 탭, 꾹 누르기의 짧은 탭. 새 제스처를
  만들지 않으니 해제와 충돌하지 않는다.
- **제한된 설정 안내는 추정으로만.** 설치 출처가 스토어도 adb(`null`)도 아니고 API 33+ 면 보인다.
  "제한됐는지" 를 직접 묻는 공개 API 가 없어 막지는 않는다.
- **타이머는 해제 수단이 아니다.** 실패하면(서비스가 죽으면) 차폐가 그대로일 뿐이고, 원래 해제 제스처는
  그대로 동작한다. 새 탈출구를 만드는 게 아니라 기존 탈출구에 하나를 더하는 것이다.
