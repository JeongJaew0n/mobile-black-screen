# 공유했을 때 생기는 문제 — 기능별

> 2026-09-23 기준. 이 문서는 **의견**이다 — 코드와 실측에서 확인한 사실과, 거기서 추론한 위험을
> 구분해 적었다. "미검증" 이라고 쓴 것은 실제로 해 보지 않은 것이다.

이 앱은 처음부터 **한 사람이 한 기기에서** 쓰려고 만들었다. 그 전제가 코드 곳곳에 깔려 있고,
남에게 건네는 순간 전제가 깨지는 자리가 문제가 된다.

## 0. 이 앱이 깔고 있는 전제

| 전제 | 어디에 박혀 있나 | 남에게 주면 |
|---|---|---|
| 사용자 = 개발자. 어떻게 푸는지 안다 | 해제 제스처에 화면 단서가 없다(3회 탭·꾹 누르기·더블 탭). 온보딩 없음 | **처음 켠 사람은 못 푼다** |
| adb 가 손에 있다 | 응급 탈출이 `am force-stop`. 접근성 재활성화도 adb 명령 | 갇히면 재시작뿐. 접근성이 꺼진 이유를 모른다 |
| 기기 한 대 — Galaxy S23+ / Android 16 / AMOLED | 모든 실측(전력·밝기·창 프레임·지문)이 이 기기 것. minSdk 26 이지만 Android 8~15 는 안 돌려 봤다 | LCD·다른 제조사·옛 버전은 전부 미검증 |
| 사이드로딩, Play 심사 없음 | `specialUse` FGS, 접근성 서비스, 알림 접근을 사유서 없이 쓴다 | Play 에 올리면 세 가지 모두 심사 대상 |
| 디버그 빌드를 직접 설치 | 릴리스 서명 설정이 없다(`isMinifyEnabled=false` 만). `assembleDebug` 로만 빌드해 왔다 | 다른 기계에서 빌드한 APK 는 **서명이 달라 갱신이 거부된다** |
| 문제가 나면 내가 logcat 을 본다 | 크래시 수집 없음. `runCatching` 21곳이 조용히 삼킨다 | 남의 기기에서 무엇이 실패하는지 알 길이 없다 |

## 1. 막힘 — 이대로 주면 못 쓴다

### 1-1. 접근성 서비스를 켤 수 없다 (Android 13+, 사이드로딩)

**기본 모드 FULL 이 통째로 걸린다.** Android 13 부터 브라우저·파일 관리자로 설치한 APK 는
접근성 서비스와 알림 접근 토글이 **"제한된 설정"** 으로 막힌다. 켜려고 하면 "보안을 위해 이
설정은 현재 사용할 수 없습니다" 만 뜬다. 푸는 길은 앱 정보 → ⋮ → "제한된 설정 허용" 인데,
**앱이 이걸 어디에도 안내하지 않는다** — 설정 화면의 `PermissionCard` 는 접근성 설정으로
보내기만 한다.

- 개발자는 안 겪은 이유: `adb install` 은 설치자가 shell 이라 제한에 안 걸린다.
- 재생 바(알림 접근)도 같은 벽에 걸린다.
- Play 로 설치하면 안 걸린다. 사이드로딩 전용 문제다.

### 1-2. 갱신하면 접근성이 조용히 꺼진다

재설치·업데이트·강제 종료가 접근성 서비스를 끈다(`troubleshootings/reusable/accessibility-service-silently-disabled-by-reinstall.md`).
그러면 **FULL 이 아무 말 없이 안 켜진다.** 앱을 열어야 카드가 보이고, 타일이나 버블로만 쓰는
사람은 "고장났다" 로 끝난다. 개발자는 매번 adb 로 다시 켰다.

- 새 APK 를 건네는 것 자체가 매번 이 문제를 만든다.
- 사용자가 "최근 앱에서 밀어서 종료" 만 해도 같은 상태가 된다 — 실사용에서도 걸린다.

### 1-3. 서명이 없어 갱신이 안 된다

디버그 키스토어는 기계마다 다르다. 다른 기계에서 빌드하거나 키스토어가 바뀌면 받는 쪽은
**삭제 후 재설치**해야 하고, 그러면 설정·접근성 토글·알림 접근이 전부 날아간다(1-2 와 겹침).
`versionCode` 도 1 에 고정돼 있어 갱신 순서를 시스템이 판단할 수 없다.

### 1-4. 어떻게 푸는지 모른다

해제는 단일 탭이 아니다(주머니 오작동 때문). 그런데 기본값 3회 탭·꾹 누르기·더블 탭은 **화면에
아무 단서가 없다.** 코드 주석이 이미 인정한다 — "다른 제스처들은 알려주지 않으면 알 수 없다".
지문 모드만 '잠금 해제' 버튼이 보이고, 그것도 재생 컨트롤이 있을 때만이다.

처음 켠 사람은 검은 화면을 보고 전원 버튼을 누른다. 그러면 진짜로 꺼지고, 다시 켜면 차폐가
그대로 있다(접근성 창은 화면 켜짐을 넘어 남는다). 다음은 재시작이다.

## 2. 위험 — 쓸 수는 있는데 사람을 다치게 할 수 있다

### 2-1. 전화·알람·긴급 알림이 가려진다 (미검증)

`TYPE_ACCESSIBILITY_OVERLAY` 는 상태바·시스템 다이얼로그 위까지 덮는다. 그게 이 모드를 고른
이유인데, 뒤집으면 **전화 수신 화면·알람 화면·긴급 재난 문자도 덮인다** 는 뜻이다. 소리는
나지만 화면은 검다. 받으려면 해제 제스처를 알아야 한다(1-4 로 돌아간다).

- PIN 입력 화면은 시스템이 접근성 창을 강제로 걷어 준다(실측). 전화·알람도 그런 보호 대상인지는
  **모른다.** 확인해야 한다.
- 개인용에선 "내가 켰으니 내가 안다" 로 넘어갔다. 남은 모른다.

### 2-2. 갇힘 — 지문 모드

지문만 허용하고 PIN 대체를 막았다가 개발자가 실제로 갇혔다
(`troubleshootings/reusable/biometric-only-unlock-locks-user-out.md`). 지금은 PIN 대체와
오류 시 자동 해제가 들어가 있다. 그래도:

- 지문이 등록되지 않은 기기·API 27 이하에서 이 옵션이 어떻게 보이는지 **확인이 필요하다.**
- 응급 탈출이 "전원 버튼 길게 → 재시작" 뿐이다. 개발자에게 있던 `adb force-stop` 은 남에게 없다.

### 2-3. 자동 종료가 없다 — 밤새 켜진 채 방전

차폐는 `FLAG_KEEP_SCREEN_ON` 으로 화면을 계속 켠다. 실측상 실제 꺼짐보다 **8시간에 17%p** 더
쓴다(`power-measurement.md`). 켜 놓고 잊으면 그대로 간다. 자동 종료 타이머·근접 센서 포켓
모드는 "아직 하지 않은 것" 목록에 있다. 개인용에선 습관으로 덮었다.

### 2-4. 블루투스 볼륨 — 미검증

미디어 소리 끄기는 "블루투스로 듣는 중이면 건너뛴다" 가 설계인데 **기기가 없어 검증하지
못했다.** 판단이 실패하면 "끄지 않는" 쪽으로 기울여 두었으니 소리가 갑자기 멎는 방향은
아니지만, 남에게 주면 블루투스 이어폰이 가장 흔한 경로다. `isVolumeFixed` 기기도 미검증.

### 2-5. 주머니 오작동

3회 탭이 기본인 이유가 주머니다. 그런데 주머니 안에서 재생 컨트롤(44dp 버튼 셋)은 여전히
눌린다 — 곡이 넘어가거나 멎는다. 개인용에선 "그럴 수 있지" 였다.

## 3. 신뢰 — 왜 이 권한이 필요한지 설득할 수 없다

| 권한 | 실제로 하는 일 | 사용자 눈에는 |
|---|---|---|
| 접근성 서비스 | 창을 올릴 자격만. `canRetrieveWindowContent=false` — 화면을 읽지 않는다 | "화면 내용을 보고 제어할 수 있음" 경고. 은행 앱이 이걸 켜 두면 실행을 거부하기도 한다 |
| 알림 접근 | `MediaSessionManager` 가 요구하는 자리. 콜백이 전부 비어 있다 — 알림을 읽지 않는다 | "모든 알림을 읽을 수 있음" 경고 |
| 다른 앱 위에 표시 | 버블 | 익숙한 편 |
| 상시 알림 | FGS 요구사항 | "왜 항상 떠 있어?" |

**앱이 이걸 설명하는 문장은 접근성 설명 한 줄뿐이다.** 프라이버시 고지도, "읽지 않는다" 는
약속을 사용자에게 보여 주는 자리도 없다. 코드 주석에만 있다.

유리한 사실 하나 — **`INTERNET` 권한이 없다.** 이 앱은 네트워크를 쓸 수 없고, 그건 매니페스트로
증명된다. 설득할 때 첫 문장으로 쓸 만하다.

**은행·보안 앱 충돌**은 실사용에 걸린다. 접근성 서비스가 켜져 있으면 실행을 막는 금융 앱이
있다(오버레이 탐지·접근성 탐지). 개발자는 그런 앱을 안 쓰거나 우회했을 수 있지만, 남은 "이 앱
켜면 은행 앱이 안 열려" 를 겪는다. 미검증.

## 4. 품질 — 한 기기에서만 맞다

| 항목 | 상태 |
|---|---|
| **LCD 기기** | 검정이 발광하지 않는 AMOLED 전제. LCD 는 백라이트가 남아 "꺼진 것처럼" 안 보이고 전력 이득도 거의 없다. README 가 한 줄 경고할 뿐, 앱은 패널 종류를 보지 않는다 |
| **Android 8~15** | minSdk 26 이지만 전부 미검증. 걸릴 만한 곳: 타일 `startActivityAndCollapse` 의 API 33 이하 분기(lint 오탐 suppress), `specialUse` 는 API 34+ 만 의미, `POST_NOTIFICATIONS` 는 33+, 지문은 28+ |
| **다른 제조사** | 창 프레임 `[0,94][1080,2214]` 같은 값은 S23+ 실측. 코드는 `usableSize()` 로 재지만 다른 기기에서 확인한 적 없다. 제조사 배터리 최적화(절전 앱·딥 슬립)가 FGS 나 접근성 서비스를 죽이는지도 모른다 |
| **업무용 기기** | 관리자가 접근성 서비스·오버레이를 막을 수 있다. 그러면 FULL 도 버블도 안 되는데 Overlay·Blackout 은 `available=false` 로 숨겨 두었다 — 대체 경로가 사용자에게 없다 |
| **언어** | en·ko 만. 다른 로케일은 영어로 떨어진다(정상). 시계·날짜 패턴은 ICU 가 로케일에서 만들어 문제없다. RTL 은 "필요 없다" 로 범위 밖 |
| **전력 기대치** | "화면 끄기" 로 소개하면 실제 꺼짐과 같을 거라 기대한다. 실측은 **87 mA 추가**다. 이걸 안 말하면 "배터리 더 먹는다" 로 돌아온다 |
| **`allowBackup=true`** | 설정이 구글 백업으로 다른 기기에 복원된다. `savedMediaVolume` 같은 런타임 잔재도 함께 — 새 기기에서 앱을 처음 열 때 볼륨을 건드릴 수 있다 |

## 5. Play 에 올린다면 추가로

사이드로딩 문제(1-1, 1-3)는 사라지고 심사가 대신 온다.

- **접근성 서비스 정책** — 접근성 목적이 아닌 사용은 별도 신고서와 "눈에 띄는 고지" 가 필요하고,
  거부되는 경우가 잦다. 이 앱의 용도("창을 올리기 위해") 는 정확히 그 범주다.
- **알림 접근** — 같은 종류의 고지 요구. 콜백이 비어 있다는 것은 심사자가 볼 수 없다.
- **`specialUse` FGS** — 사유서 제출. 매니페스트의 `PROPERTY_SPECIAL_USE_FGS_SUBTYPE` 한 줄로는
  부족할 수 있다.
- **targetSdk** — 지금 36. Play 는 최신에서 1년 이내를 요구하니 매년 올려야 하고, 그때마다
  검증 범위 문제(`CLAUDE.md` "targetSdk 를 올리지 말 것")가 되돌아온다.
- 프라이버시 정책 URL, 데이터 안전 섹션 — 지금 없다.

## 6. 공유 전에 할 것 — 순서대로

이 문서는 "하지 마라" 가 아니라 "이 순서로" 다. 위가 급하다.

1. **릴리스 키스토어 만들고 `versionCode` 를 올리는 습관** — 안 하면 갱신마다 1-3 이 반복된다.
2. **제한된 설정 안내** — `PermissionCard` 에 "Android 13+ 에서 사이드로딩이면 앱 정보 → ⋮ → 제한된
   설정 허용" 을 넣는다. 이게 없으면 기본 모드가 안 켜진다.
3. **접근성이 꺼졌을 때 알리기** — 타일·버블에서 FULL 을 켰는데 서비스가 없으면 토스트나
   알림으로 "접근성이 꺼져 있다" 를 말한다. 지금은 조용히 실패한다.
4. **해제 방법을 화면에** — 첫 차폐 때 한 번, 또는 밝기 0 이라 안 보이니 차폐 직전 토스트로
   "3번 탭하면 풀립니다". 최소한 설정 화면 첫 줄에.
5. **전화·알람 가림 확인** — 실기기에서 전화를 걸어 본다. 가려지면 "전화 오면 자동 해제" 가
   필요한지 정한다.
6. **자동 종료 타이머** — 공유 상대가 잊고 재울 것을 전제로.
7. **권한 설명 한 화면** — 접근성·알림 접근이 각각 무엇을 하고 무엇을 안 하는지, `INTERNET` 이
   없다는 사실. 코드 주석에 있는 문장을 사용자에게 보여 주면 된다.
8. **블루투스 이어폰으로 미디어 소리 끄기 검증** — 기기 하나 빌리면 된다.
9. **크래시 수집** — 네트워크 없이 하려면 로그를 파일로 남기고 "문제 신고" 에서 공유 시트로.
   `INTERNET` 없음을 지키는 쪽이 신뢰 면에서 낫다.

Play 라면 여기에 §5 가 더해진다. 그건 기능이 아니라 문서와 심사의 일이다.

## 7. 개인용으로 남겨도 되는 것

공유해도 문제가 **안 되는** 것도 적어 둔다 — 고칠 것과 안 고칠 것을 가르기 위해.

- 시계·날짜 패턴 — ICU 가 로케일별로 만든다. 어느 나라 사용자든 맞다.
- 번인 방지 — 끌 수 없고 늘 돈다. 남의 패널도 지킨다.
- 밝기 0 기본 — 표시할 내용이 없으면 무조건 0. 설정을 안 건드린 사용자에게 가장 안전한 상태다.
- 설정 저장 — 변환 함수로 저장해 부분 덮어쓰기 문제가 없다.
- 미디어 제어 — 미디어 버튼 이벤트라 앱 호환성이 넓다.
- 디자인 토큰 — 공유와 무관. 다만 "내 폰에 맞춘 값" 이 한 파일에 모여 있어 남의 기기에 맞출 때
  손댈 자리가 분명하다.
